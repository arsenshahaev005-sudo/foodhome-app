# Задача для food-home: совместимость APK 0.2.6

В foodhome-app подготовлена Android-версия **0.2.6 / build 8**: фирменный
значок вместо колокольчика и цветной логотип в уведомлениях. Контракт bridge
остаётся **1.7.0**, формат push, типы событий и звук не менялись.

Сейчас `_SELLER_NEW_ORDER_RELEASES` в
`backend/api/services/native_push_delivery.py` разрешает `seller.order.new`
только для `(1.7.0, 0.2.5, 7)`. Без серверного изменения новая версия при
актуальных данных установки будет получать обычное `order.updated`.

## Простой промпт

Нужно сохранить специальный звук новых заказов продавцу после обновления
Android-приложения до 0.2.6 / build 8.

Сначала изучи AGENTS.md, память и фактический код food-home. Проверь опубликованные
изменения foodhome-app: новая версия меняет только оформление уведомлений,
а bridge остаётся 1.7.0. Не считай локальную ветку опубликованным релизом:
до принятого native commit и проверки исходников оставь публикацию заблокированной.

После проверки добавь точную комбинацию `(1.7.0, 0.2.6, 8)` в существующий
список совместимых версий, сохранив поддержку `(1.7.0, 0.2.5, 7)`.
Не разрешай автоматически все будущие версии.

Добавь тесты: обе подтверждённые версии получают seller.order.new только для
действительно нового заказа продавцу; старые и неизвестные версии получают
прежнее order.updated; покупатель, чат и обычные изменения заказа не получают
специальный звук. Сохрани проверку получателя, согласия, актуальной привязки,
срока действия и защиту от дубликатов, в том числе при отправке из очереди.

Проверь, что после обновления приложения данные его версии в существующей
привязке обновляются штатным безопасным способом. Не подменяй их вручную в БД.
Если обновление метаданных требует отдельной правки, покажи конкретную причину
и согласуй объём, не скрывай это повторным использованием старого номера APK.

Репозиторий foodhome-app не изменяй. Не меняй БД вручную, production-флаги,
credentials и не отправляй реальные уведомления без отдельного согласования.
В конце объясни, что проверено и что осталось для выкладки.

## Статус на момент подготовки

Native-изменения локальные; commit/PR/CI/merge ещё не выполнены. APK 0.2.5
по выбору владельца остаётся на телефоне до согласованного rollout. Этот документ
не подтверждает ни деплой сервера, ни приёмку нового APK на реальном устройстве.
